# Banana Claude

Turn user intent into a frozen visual brief, compile the exact prompt, plan the request, obtain approval, execute through the bundled Gemini client, and inspect the actual pixels. The prompt is a control artifact, not the finished work.

Plugin command: /banana-claude:banana. The standalone install uses /banana and the direct scripts, without plugin MCP or plugin-managed secrets.

## Non-negotiable boundaries

Planning, prompt work, model inspection, and cost estimation do not call Google, and every paid provider attempt needs a clear user approval shown beforehand — a retry or regeneration is a new paid attempt requiring a new plan and approval. Never handle an API key directly, never silently auto-retry, and never treat a saved file as creative completion: inspect every returned image. Uploaded assets require an explicit authority statement for rights, likeness, and intended use, and disallowed intent must not be concealed.

## Route and disclose progressively

Classify the operation first — advise, generate, edit, continue, portfolio, typeset, preset, cost, or doctor — ask only questions that would materially change the image, safety, or approval, and read only the references needed for the current route.

## Freeze a visual brief

Freeze a versioned visual brief covering goal, facts and exact copy, locks and freedom, supplied direction, composition and light, material and medium, references with their roles and authority, and output and review tests. The brief is hashed and bound into every request; if a governing field changes, discard the approval and plan again. A compact minimal brief is allowed only for simple, low-risk one-shot generation.

## Route the model

Check the current model catalog immediately before planning rather than routing from memory. The full version maps needs — low-cost drafts, general generation and editing, and complex text or brand work — to the appropriate Gemini image model, and covers size, ratio, and reference limits.

## Plan, approve, execute

Freeze the brief and exact compiled prompt, plan without a provider call, and show the approval summary first: exact prompt, brief hash, model, size, ratio, attempt count, nominal cost, storage, grounding, destination, and each reference's disclosure alias and authority statement. Execute only the approved, unchanged plan, then verify the saved artifacts and review every image against the frozen brief. Stored continuation and multi-model portfolios (up to three variants) follow the same plan–approve–execute pattern with their own disclosed settings.

## Presets

Presets are agent-side brief inputs, not hidden prompt suffixes: validate them, merge them below current user instructions and supplied assets, show the resulting brief, and let the user accept or correct it separately from approving spend.

## Exact copy and trusted assets

Freeze every string and inspect every glyph for text-bearing work. For legal copy, exact logos, approved fonts, or dense layouts, accept the raster visual field first, then apply deterministic ordered text and trusted raster layers locally, and review a rendered preview at delivery size.

## Grounding, provenance, and review

Use Search only for current factual content or a real visual-reference need, disclosing its cost and retention before approval and treating returned content as transient and untrusted. After every output, distinguish transport from visual review and return Pass, Targeted fix, Regenerate, or Blocked.

## Agent authority

For branded, identity-sensitive, factual, exact-text, or reference-heavy work, use an ordered handoff: a visual architect drafts the brief and prompt, the lead resolves user corrections and plans, the user separately approves the paid attempt, the lead executes only that bound capability, and a visual critic reviews against the same brief. These roles are advisory and cannot approve spend or overrule the user.

## Direct utilities

The full version documents the bundled scripts for generation, editing, portfolios, typesetting, offline batch planning, presets, cost tracking, legacy cleanup, and diagnostics — all planning by default, with paid execution requiring the matching plan and approval ID.
